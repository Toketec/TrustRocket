# TrustRocket 项目契约

## 工作边界

本项目只使用装备材料、技术支持、案例沉淀和一线运营四个一级业务域。执行者可以是 Human、AI Agent、Script、Automation、External Service 或组合；更换执行者不改变目标、输入输出、验收与权限边界。

TrustRocket 不是 CRM、工单系统、客户数据库、在线客服、知识库产品或 Agent 平台。任何软件只负责承载或执行部分能力。

## 内容结构

每个业务域根部平铺业务 Markdown，`source/` 保存原始材料，`cut/` 保存从原始材料切出的独立资源。不得自行新增其他业务子目录；超出模型时先说明原因并取得决定。

用户提供的素材与由其切出的资源使用 `user-` 前缀。公共来源素材不使用该前缀。素材来源登记在 `.trustrocket.json`。

默认使用 Markdown、JSON、YAML、TOML、CSV、Mermaid 与脚本。只有明确要求时生成 DOCX、XLSX、PPTX、PDF 或图片，文本源原则上保留。

## Markdown 规则

业务 Markdown 最多三级标题。一个标题只要有子标题，就只承担结构作用，不直接承载正文；正文只位于叶子标题下。

装备材料以最小充分信息帮助目标读者快速行动。按场景选择适用结构，不机械增加背景、总结或无价值章节。

## 闭环规则

技术问题解决后判断是否需要：创建或修正案例、修正装备、更新一线运营状态、向 SpecRocket 输出产品缺陷 Handoff。

案例必须说明场景、环境、判断、处理、原因、结果、复用条件和不适用条件。运营状态只描述客户、项目、POC、交付、故障、服务、风险与外部依赖等真实业务对象。

禁止记录 TrustRocket 项目自身的编辑进度、维护状态、AI 工作日志、待办、路线图或下次工作。Git 保存内容演化历史。

## 权限规则

AI 可在授权范围内搜索、分析、汇总、草拟、诊断、提议和执行低风险操作。删除或覆盖数据、生产高风险操作、客户核心配置、安全策略、商业承诺、合同责任、重大客户沟通、重大事故定级与重大恢复必须由获授权角色确认。

权限不清、信息不足或风险超出范围时停止相关动作，保留证据并升级。

## Git 规则

默认禁止自动提交、推送、标签、合并、变基和发布。只读查看状态、差异与历史允许；所有 Git 写操作需使用者明确要求。
